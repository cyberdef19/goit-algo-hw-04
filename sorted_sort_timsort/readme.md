Порівняння трьох алгоритмів сортування: 

*алгоритм вставками,\
*алгоритм злиттям,\
*алгоритм Timsort

Для порівняння алгоритмів застосовувалися псевдовипадкові числа,
що генерувалися генератором random.randint. Масиви даних обиралися 
різними за розмірами: 1000 псевдовипадкових елементів, 10000 елементів
та 100000 елементів. 

Для порівняння часу виконання між цими трьома алгоритмами сортування використовувався
timeit. Для псевдовипадкових даних розміром 1000 елементів алгоритм вставками проганявся
1000 разів, а інші два проганялися по 2000 разів. Для розміру масиву даних у 10000 прогон 
склав 100 для алгоритма вставками, по 500 для алгоритмів злиття та Timsort. Для розміру 
масиву даних у 100000 елементів прогон алгоритму вставками склав 10 разів, а інші два алгоритми
по 50. Таке зниження кількісті прогонів знадобилося, щоб завершити завдання за прийнятний
період часу.

В теорії заявляється, що алгоритм сортування вставками є хорошим для невеликих розмірів даних та виявляється 
повільнішим за два інших алгоритми. Часова складність алгоритму визначається лінійною O(n), тоді як часова
складність алгоритму злиття є лінійно-логарифмічною O(n*log n), такою ж є часова складність алгоритма TimSort.

На практиці маємо наступні результати. Щоб ці результати мали адекватний вид, потрібно було декілька десятків,
а то і сотень разів проганяти алгоритм на псевдовипадкових даних. 
При розмірі даних 1000 елементів маємо

Insertion sort : 22.324652\
Merge sort: 3.091677 сек\
Sorted sort: 0.153839 сек

При розмірі даних 10000 елементів:

Insertion sort : 251.151868\
Merge sort: 10.386506 сек\
Sorted sort: 0.526458 сек

І при розмірі даних у 100000 псевдовипадкових елементів

Insertion sort : 3111.629768 сек\
Merge sort: 13.915604 сек\
Sorted sort: 0.735376 сек

Як бачимо, алгоритм сортування вставками дійсно сильно повільніший за два інші алгоритми.
Особливо це помітно, коли зростає об'єм масиву даних - 22 секунди при 1000 елементів та 
3111 секунд при 100 тисячах елементів. Авжеж, кількість прогонів тут нерівна, але закономірність очевидна

Помітно зростає і сортування злиттям. Цей алгоритм швидший за сортування 
вставками. Але він повільніший за ТімСорт, що є гібридом цих алгоритмів.
Як бачимо, при зростанні кількості даних алгоритм ТімСорт для виконання потребує
менше секунди. Тому цей алгоритм дійсно є швидким у порівнянні зі своїми побратимами
алгоритмами вставки та злиття.
